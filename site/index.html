What it writes

The rust-cli preset emits seven paths. Each exists to stop a decision being remade on the next project — the whole argument for a scaffolding tool is that these choices were already settled.

scaffolds/rust-cli.yaml The one authored input. Everything below is generated from it.
Cargo.toml Edition 2024, MIT, empty dependency block.
src/main.rs A compiling entry point, so the first command is not a build failure.
Justfile fmt, check, lint, test, and a composite gate.
CLAUDE.md Project conventions, written once instead of corrected repeatedly.
.gitignore Build output, secrets, and a fenced handoff block.
.ctx/HANDOFF.yaml Session state, gitignored except the source document.
README.md Usage and development commands.

The scaffold refuses to be a template you cannot read. Every file is small, commented, and meant to be edited on first use.

Presets

Presets are declared in scaffolds/*.yaml and enumerated in the domain layer. The enum is #[non_exhaustive], so adding a preset is a deliberate change rather than an accident.

rust-cli Preset available today
4 Modules in the crate
7 Files per scaffold
0 Framework dependencies

RustLib, GoCli, and NuScript are marked for addition. None ship yet, and the CLI reports an unknown preset name as an error rather than guessing.

Commands

CommandEffect
sparkfile new rust-cli <name> Scaffold into the current directory.
--description <text> Seeds the description into README and CLAUDE.
--root <path> Scaffold somewhere else, such as a workspace root.

Project names are validated before anything is written, so a rejected name leaves no partial directory behind.

Modules

Four small modules with an explicit domain boundary, which is the same rule the generated CLAUDE.md asks of new projects.

ModuleResponsibility
domainPresets, project specs, and name validation.
scaffoldLoading YAML and interpolating {{name}}.
fsWriting generated files, with real errors.
mainArgument parsing and dispatch.
